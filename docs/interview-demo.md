# RAG 五分钟面试演示

演示页：[HRP 知识库问答](https://rag-knowledge-base01.streamlit.app/)。

当前实时检索使用 12 篇医院运营示例文档：8 篇原始资料和 4 篇作者编写的演示规则，均不作为实际医院制度。页面区分实时检索、历史评估回放与模型生成。当前公网尚未配置生成服务，能现场输入新问题并检查检索片段，不能把检索片段介绍成模型生成的回答。

## 面试前准备

打开演示页，选择“药品和耗材入库要核对什么？”，点击“提问”，等到完整来源出现。首次请求会下载模型并重建索引；完成一次提问后再开始正式演示。确认“混合检索 + 精排”正常，另备“混合检索”作为精排加载失败时的选择。

提前打开 GitHub 的本指南和 `eval_data/eval_result.json`。页面提供完整评估记录下载，可提前保存为证据备份。历史回放不调用模型；如果整个网站或网络不可用，已下载的记录仍能展示真实实验。

## 五分钟演示顺序

1. **0:00–0:40，交代范围。** “这是医院运营示例知识库。我用统一的检索管线接入 FastAPI 和 Streamlit，比较纯向量、混合检索与精排。现在现场演示实时检索和原文核对；页面也明确显示生成服务的配置状态。”
2. **0:40–1:40，现场提问。** 选择“药品和耗材入库要核对什么？”，点击“提问”。检查本次问题、模式和耗时，展开来源 `[1]`，逐项核对品名、规格、数量、批号、有效期等原文。片段未覆盖问题时如实说明，不能只凭返回了五个候选就认定有答案。
3. **1:40–2:40，解释改进。** 切换“历史评估回放”，选择“耗材是怎么直接送到科室的？”。同一份保存记录中，纯向量前五名没有命中标注片段，混合检索排在第四，精排后排在第一。展开三列片段核对，而不是只展示一个百分比。此处是 2026-09-30 的历史运行，当前重新检索的排序不一定完全相同。
4. **2:40–3:40，展示整体证据。** 指出 28 题中 Hit@5 为 92.86% → 100%，MRR 为 0.8423 → 0.9464，NDCG@5 为 0.8558 → 0.9561。MRR 和 NDCG 相对纯向量分别提升约 12.4% 和 11.7%。展开“指标含义与复现信息”，展示模型名称、分块设置、数据哈希，再下载完整记录。不要把这组检索指标说成回答准确率。
5. **3:40–5:00，解释取舍并接新问题。** 回到实时检索，允许面试官改写问题。切换模式后，页面保留的旧结果仍标注原模式；需要再点击“提问”才能产生新结果。说明精排通常增加计算开销，并展示单次请求耗时。这个耗时包含本次加载时间，不是严谨的性能基准。

如果追问覆盖规模，可在历史回放选择“扩展60题（12篇资料）”：展示48个可回答题的三路结果，再选择一个无答案问题。后者只显示候选，不给倒数排名，也没有生成拒答结论。V2的题目与资料由项目协作编写，不能把这组满分结果当作第三方盲测或回答准确率；两个版本的语料和题集不同，也不能直接计算分数提升。详情见[评估V2说明](evaluation-v2.md)。

## 实现与取舍

- 文档解析后先按标题保留上下文，再按中文标点切成约 400 字、重叠 50 字的片段。BGE 向量检索处理语义改写，BM25 补充领域术语和缩写，RRF 用排名融合两路候选，避免直接混加不同尺度的分数。
- Cross-Encoder 只精排前 10 个候选，返回 5 个来源片段。它提高了这组样本的整体排序，但不是所有题都进步：历史记录中“设备折旧影响成本吗？”由纯向量第一名退到第二名，“医院物资管理的五个环节是什么？”也存在精排退步。
- 原始历史评估使用8篇、32个片段；当前扩展语料为12篇、52个片段，用 FAISS 和 BM25 可以直接展示完整流程；目前没有必要引入额外数据库或平台。Streamlit 与 FastAPI 复用 `src/retrieval.py`，生成链使用页面实际显示的同一批来源及编号。
- 生成链在提示中要求只依据资料、附引用并对资料未覆盖的问题说明无法回答。提示要求不等于已验证拒答：现有 28 题只覆盖有答案问题，没有生成事实准确率或无答案拒答评估。可以问“医院食堂本周菜单是什么？”展示这一边界，不要将最近邻候选包装成菜单答案。

## 出错时怎么继续

- **精排加载失败：** 改为“混合检索”或“纯向量”，重新点击“提问”。当前页面错误不会阻止切换历史回放。
- **模型下载或索引加载失败：** 切到“历史评估回放”，明确告知正在查看保存记录，不声称是现场计算。
- **生成服务未配置：** 勾选项禁用，继续展示检索与来源；不要在面试时临时购买服务。
- **生成途中失败：** 页面会标记“生成未完成”，保留原文来源供核对。关闭生成后重新提问；部分文字不能当作完整回答。
- **网站或网络不可用：** 展示提前下载的完整评估记录和仓库源码，说明公网演示暂时不可用。

## 复现和验收

在仓库根目录执行：

```bash
python -m scripts.evaluate 5 --questions eval_data/test_questions_v2.json --output eval_data/eval_result_v2.json
python -m pytest tests -q
streamlit run streamlit_app.py
```

该命令更新独立V2记录，不覆盖原28题。复现历史数字须恢复原8篇语料和对应环境。自动检查覆盖指标计算、检索、完整来源、真实流式消费，以及演示页的状态保持、空输入、失败恢复和历史回放；它们不会代替真实公网模型服务验收。

人工验收需要确认：选示例会填入输入框但不提前加载模型；提交后出现完整来源；修改模式不会把旧结果误标成新模式；历史回放的三列与 JSON 相符；未配置生成时禁用生成选项。如果未来接入生成服务，还需实际提问并观察逐段输出及引用对应关系，才能称为公网流式问答演示。
